# Requirements Document

## Introduction

Lotes > Controle de Lotes is a comprehensive batch/lot management module for the PSF Digital Frontend export platform. The module enables operators to manage product lots across their lifecycle — from warehouse entry through export — with real-time stock visibility, AI-powered quality insights, quality inspection records, and a full movement audit trail. The module follows the established CertificacoesComponent pattern using Angular 20 standalone components, Angular Material, inject()-based DI, and mock services with Observable returns.

## Glossary

- **LotesControle_Component**: The main Angular standalone component responsible for rendering the Lotes > Controle de Lotes module UI
- **LotesMock_Service**: The injectable mock service (providedIn: 'root') that provides lot data, filter operations, CRUD actions, and AI insights via Observables with simulated delay
- **Smart_Grid**: The MatTable-based data grid displaying lots with pagination, sorting, status chips, AI score badges, and inline action buttons
- **KPI_Dashboard**: The set of four summary cards displayed above the grid showing aggregated lot metrics
- **Detail_Drawer**: The MatDrawer side panel that shows full lot information organized in tabs
- **AI_Insights_Panel**: A fixed panel displaying AI-generated quality scores, export suggestions, anomaly alerts, and expiry predictions
- **Quick_Filters**: The set of filter controls (product, harvest, status, warehouse, country, expiry range, AI score range) above the grid
- **Global_Search**: The debounced text input field that searches across all lot fields
- **Quality_Inspection**: The sub-module for registering and viewing quality analysis parameters for a lot
- **Movement_History**: The automatic audit trail recording all lot state transitions and operations
- **Lote**: A discrete batch of export product identified by a unique lot number with associated stock, quality, and location data
- **LoteStatus**: One of six possible lot states: DISPONÍVEL, BLOQUEADO, QUARENTENA, EM_TRÂNSITO, RESERVADO, ESGOTADO
- **AILotScore**: A numeric quality score (0–100) generated by AI analysis for a given lot

## Requirements

### Requirement 1: KPI Dashboard Cards

**User Story:** As an export operator, I want to see summary KPI cards at the top of the lot control screen, so that I can quickly assess the current state of my lot inventory.

#### Acceptance Criteria

1. WHEN the LotesControle_Component initializes, THE KPI_Dashboard SHALL display a card showing the total available quantity across all lots with status DISPONÍVEL.
2. WHEN the LotesControle_Component initializes, THE KPI_Dashboard SHALL display a card showing the count of lots with status BLOQUEADO.
3. WHEN the LotesControle_Component initializes, THE KPI_Dashboard SHALL display a card showing the count of lots expiring within 30 days.
4. WHEN the LotesControle_Component initializes, THE KPI_Dashboard SHALL display a card showing the average AI quality score across all lots.
5. WHEN filter criteria change, THE KPI_Dashboard SHALL recalculate all four metrics based on the filtered dataset.

### Requirement 2: Smart Grid

**User Story:** As an export operator, I want to view lots in a sortable, paginated data grid with visual status indicators, so that I can efficiently browse and manage large volumes of lots.

#### Acceptance Criteria

1. THE Smart_Grid SHALL display lot data using MatTable with columns: lot number, product name, harvest/safra, status, warehouse, quantity, expiry date, AI score, and actions.
2. THE Smart_Grid SHALL provide MatPaginator with configurable page sizes of 10, 25, 50, and 100 items.
3. THE Smart_Grid SHALL support MatSort on all data columns.
4. WHEN a lot status is rendered, THE Smart_Grid SHALL display the status as a colored MatChip mapped to the LoteStatus value.
5. WHEN an AI score is rendered, THE Smart_Grid SHALL display the score as a MatBadge with color coding: green for 80–100, yellow for 50–79, red for 0–49.
6. THE Smart_Grid SHALL display an inline actions menu with options: view details, edit, block/unblock, and reserve for export.

### Requirement 3: Quick Filters

**User Story:** As an export operator, I want to filter lots by multiple criteria simultaneously, so that I can narrow down to specific lots of interest.

#### Acceptance Criteria

1. THE Quick_Filters SHALL provide a MatSelect for product filtering with options loaded from the LotesMock_Service.
2. THE Quick_Filters SHALL provide a MatSelect for harvest/safra filtering.
3. THE Quick_Filters SHALL provide a MatSelect for status filtering with all six LoteStatus values as options.
4. THE Quick_Filters SHALL provide a MatSelect for warehouse filtering.
5. THE Quick_Filters SHALL provide a MatSelect for destination country filtering.
6. THE Quick_Filters SHALL provide a MatDatepicker range for expiry date filtering (start and end dates).
7. THE Quick_Filters SHALL provide a numeric range input (min and max) for AI score filtering.
8. WHEN any filter value changes, THE LotesControle_Component SHALL apply all active filters to the Smart_Grid data within 300ms debounce.
9. THE Quick_Filters SHALL provide a clear-all button that resets all filter fields to their default empty state.

### Requirement 4: Global Search

**User Story:** As an export operator, I want to type a search term and have it match across all lot fields, so that I can quickly locate specific lots without knowing which field contains the data.

#### Acceptance Criteria

1. THE Global_Search SHALL provide a text input field with a search icon and placeholder text.
2. WHEN the user types in the Global_Search field, THE LotesControle_Component SHALL debounce the input by 300ms before applying the search.
3. WHEN a search term is applied, THE LotesControle_Component SHALL filter lots where the term matches any of: lot number, product name, warehouse, harvest, or destination country.
4. WHEN the search field is cleared, THE LotesControle_Component SHALL restore the full dataset (respecting any active Quick_Filters).

### Requirement 5: Lot Detail Drawer

**User Story:** As an export operator, I want to open a side panel showing complete lot information organized in tabs, so that I can review all lot details without navigating away from the grid.

#### Acceptance Criteria

1. WHEN the user clicks "view details" on a lot row, THE Detail_Drawer SHALL open as a MatDrawer from the right side.
2. THE Detail_Drawer SHALL organize lot information in five MatTabs: Dados Gerais, Estoque, Qualidade, Certificados, and Histórico.
3. WHEN the Dados Gerais tab is active, THE Detail_Drawer SHALL display lot number, product, harvest, warehouse, physical location, creation date, and current status.
4. WHEN the Estoque tab is active, THE Detail_Drawer SHALL display initial quantity, reserved quantity, exported quantity, available quantity, and current balance.
5. WHEN the Qualidade tab is active, THE Detail_Drawer SHALL display the most recent quality inspection data and the AI quality score.
6. WHEN the Certificados tab is active, THE Detail_Drawer SHALL display a list of certificates associated with the lot.
7. WHEN the Histórico tab is active, THE Detail_Drawer SHALL display the complete Movement_History for the lot in reverse chronological order.
8. WHEN the user clicks outside the drawer or presses the close button, THE Detail_Drawer SHALL close and return focus to the Smart_Grid.

### Requirement 6: AI Insights Panel

**User Story:** As an export operator, I want an AI-powered panel that provides quality scores, export suggestions, and anomaly alerts, so that I can make data-driven decisions about lot management.

#### Acceptance Criteria

1. WHEN a lot is selected, THE AI_Insights_Panel SHALL display the lot quality score as a numeric value from 0 to 100 with a visual gauge.
2. WHEN a lot is selected, THE AI_Insights_Panel SHALL display up to three export destination suggestions based on lot quality and certifications.
3. WHEN anomalies are detected for a lot, THE AI_Insights_Panel SHALL display anomaly alerts with severity level and description.
4. WHEN a lot has an expiry date, THE AI_Insights_Panel SHALL display a predicted days-to-expiry countdown and risk classification.
5. THE AI_Insights_Panel SHALL load data from the LotesMock_Service using Observable returns with simulated delay.

### Requirement 7: CRUD Operations

**User Story:** As an export operator, I want to create, edit, view, block/unblock, and reserve lots for export, so that I can fully manage the lot lifecycle.

#### Acceptance Criteria

1. WHEN the user clicks the "create lot" button, THE LotesControle_Component SHALL open a form dialog with fields for product, harvest, warehouse, initial quantity, expiry date, and physical location.
2. WHEN the user submits a valid create form, THE LotesMock_Service SHALL persist the new lot and THE Smart_Grid SHALL refresh to include the new entry.
3. WHEN the user clicks "edit" on a lot, THE LotesControle_Component SHALL open a pre-populated form dialog allowing modification of editable fields.
4. WHEN the user submits a valid edit form, THE LotesMock_Service SHALL update the lot and THE Smart_Grid SHALL reflect the changes.
5. WHEN the user clicks "block" on a lot with status DISPONÍVEL, THE LotesMock_Service SHALL change the lot status to BLOQUEADO and record the action in Movement_History.
6. WHEN the user clicks "unblock" on a lot with status BLOQUEADO, THE LotesMock_Service SHALL change the lot status to DISPONÍVEL and record the action in Movement_History.
7. WHEN the user clicks "reserve for export" on a lot with status DISPONÍVEL, THE LotesControle_Component SHALL prompt for the reservation quantity and destination, and THE LotesMock_Service SHALL change the lot status to RESERVADO and record the action in Movement_History.
8. IF a CRUD operation fails, THEN THE LotesControle_Component SHALL display an error message using MatSnackBar with a 5000ms duration.
9. WHEN a CRUD operation succeeds, THE LotesControle_Component SHALL display a success message using MatSnackBar with a 3000ms duration.

### Requirement 8: Stock Control

**User Story:** As an export operator, I want to see real-time stock levels for each lot, so that I can verify available quantities before making export decisions.

#### Acceptance Criteria

1. WHEN the Estoque tab is active in the Detail_Drawer, THE LotesControle_Component SHALL display the following fields: initial quantity (kg), reserved quantity (kg), exported quantity (kg), available quantity (kg), and balance (kg).
2. THE LotesControle_Component SHALL calculate available quantity as: initial quantity minus reserved quantity minus exported quantity.
3. WHEN the available quantity reaches zero, THE LotesMock_Service SHALL automatically set the lot status to ESGOTADO and record the transition in Movement_History.
4. WHEN a reservation is created, THE LotesMock_Service SHALL deduct the reserved amount from the available quantity.

### Requirement 9: Quality Inspection

**User Story:** As a quality inspector, I want to register quality analysis parameters for a lot, so that the lot quality data is tracked and available for AI scoring.

#### Acceptance Criteria

1. WHEN the user opens the quality inspection form for a lot, THE LotesControle_Component SHALL display input fields for: humidity (%), impurity (%), protein (%), pH, weight (kg), temperature (°C), color, odor, pest presence (boolean), and lab results (text).
2. WHEN the user submits a valid quality inspection form, THE LotesMock_Service SHALL persist the inspection record associated with the lot.
3. WHEN a new quality inspection is saved, THE AI_Insights_Panel SHALL recalculate the AI quality score for the lot.
4. THE Quality_Inspection form SHALL validate that numeric fields contain values within acceptable ranges (humidity: 0–100, pH: 0–14, temperature: -40 to 60).

### Requirement 10: Movement History

**User Story:** As an export operator, I want an automatic audit trail of all lot operations, so that I can trace the full history of any lot for compliance and investigation purposes.

#### Acceptance Criteria

1. WHEN a lot is created, THE LotesMock_Service SHALL record an ENTRY movement in the Movement_History with timestamp, user, and operation details.
2. WHEN a lot status changes (block, unblock, reserve, export), THE LotesMock_Service SHALL record the corresponding movement type in the Movement_History.
3. WHEN a lot is transferred between warehouses, THE LotesMock_Service SHALL record a TRANSFER movement with origin and destination locations.
4. THE Movement_History SHALL display entries in reverse chronological order with columns: date/time, operation type, user, origin status, destination status, and notes.
5. THE Movement_History SHALL be read-only and entries SHALL be immutable after creation.

### Requirement 11: Mock Service

**User Story:** As a developer, I want a fully functional mock service with realistic Brazilian agro export data, so that I can develop and test the UI without a backend.

#### Acceptance Criteria

1. THE LotesMock_Service SHALL be an injectable Angular service with providedIn: 'root'.
2. THE LotesMock_Service SHALL return Observables with a simulated delay between 200ms and 800ms using the RxJS delay operator.
3. THE LotesMock_Service SHALL provide at least 20 mock lot records covering products: soja (soy), milho (corn), café (coffee), açúcar (sugar), and carne (meat).
4. THE LotesMock_Service SHALL provide methods for: getLotes, getLoteById, createLote, updateLote, blockLote, unblockLote, reserveLote, getMovementHistory, getQualityInspections, saveQualityInspection, getAIInsights, and getKPIMetrics.
5. THE LotesMock_Service SHALL maintain in-memory state so that CRUD operations persist during the session.

### Requirement 12: Types Definition

**User Story:** As a developer, I want well-defined TypeScript interfaces for all lot-related entities, so that the codebase has type safety and clear data contracts.

#### Acceptance Criteria

1. THE types file SHALL define the Lote interface with properties: id, loteNumber, productName, productId, harvest, status, warehouseId, warehouseName, quantity, reservedQuantity, exportedQuantity, availableQuantity, expiryDate, physicalLocation, aiScore, createdAt, updatedAt, and destinationCountry.
2. THE types file SHALL define the LoteStatus type as a union of: 'DISPONÍVEL' | 'BLOQUEADO' | 'QUARENTENA' | 'EM_TRÂNSITO' | 'RESERVADO' | 'ESGOTADO'.
3. THE types file SHALL define the QualityInspection interface with properties: id, loteId, humidity, impurity, protein, pH, weight, temperature, color, odor, pestPresence, labResults, inspectedBy, inspectedAt.
4. THE types file SHALL define the StockMovement interface with properties: id, loteId, movementType, fromStatus, toStatus, quantity, userId, userName, timestamp, notes.
5. THE types file SHALL define the PhysicalLocation interface with properties: warehouseId, section, row, position.
6. THE types file SHALL define the AILotScore interface with properties: loteId, score, exportSuggestions, anomalyAlerts, expiryPrediction, calculatedAt.
7. THE types file SHALL define the LoteFilters interface with properties: searchText, product, harvest, status, warehouseId, destinationCountry, expiryDateStart, expiryDateEnd, aiScoreMin, aiScoreMax.
8. THE types file SHALL be located at src/types/lotes.ts.

### Requirement 13: Route Registration

**User Story:** As a developer, I want the Lotes Controle module registered as a lazy-loaded route, so that users can navigate to it and it loads on demand.

#### Acceptance Criteria

1. THE route configuration SHALL register the path 'lotes/controle' under the 'home-logged' parent route.
2. THE route SHALL use loadComponent to lazy-load the LotesControle_Component.
3. THE route SHALL be placed before the wildcard catch-all route ('**') in the route array.
4. WHEN the user navigates to '/home-logged/lotes/controle', THE Angular router SHALL render the LotesControle_Component.
